1 60-Second Pitch

CSharpCache is a from-scratch, in-process TTL cache for .NET 10, built to understand cache internals deeply — not to ship to prod (yet). It stores arbitrary values keyed by string, expires them by absolute or sliding TTL measured in Stopwatch.Frequency ticks (not wall-clock DateTime), and cleans up expired entries on a background sweep timer.

All mutation is lock-free via ConcurrentDictionary + Interlocked. The interface is dead simple: Set / TryGet / Remove. A metrics snapshot gives you hits, misses, hit-rate, and expiry counts for free.

4 Annotated — TryGet TtlCache.cs:99

This is the hot path. It handles miss detection, sliding-window refresh, and hit counting — all without a lock.

public bool TryGet(string key, out TValue value) {
    ArgumentNullException.ThrowIfNull(key);

    var cacheHit = _store.TryGetValue(key, out var cacheEntry);
    var timeNowTicks = Stopwatch.GetTimestamp(); // high-res, monotonic

    if (!cacheHit || cacheEntry.DeadlineTicks <= timeNowTicks) {
        // Miss: not found OR found-but-expired → treat as miss
        Interlocked.Increment(ref _misses);
        value = default!;
        return false;
    }

    Interlocked.Increment(ref _hits); // only incremented on live hit

    var remaining = cacheEntry.DeadlineTicks - timeNowTicks;
    if (remaining <= cacheEntry.SlidingWindowTicks / 3) {
        // ⚠ Refresh only when < 1/3 of the sliding window remains
        // Not on every read — intentional batching to avoid CAS storms
        var refresh = timeNowTicks + cacheEntry.SlidingWindowTicks;
        var newDeadlineTicks = cacheEntry.AbsoluteCapTicks > 0
                ? Math.Min(refresh, cacheEntry.AbsoluteCapTicks)
                : refresh; // AbsoluteCapTicks==0 means no absolute cap

        if (newDeadlineTicks > cacheEntry.DeadlineTicks) {
            var newEntry = new CacheItem<TValue>(
                cacheEntry.Value, newDeadlineTicks,
                cacheEntry.SlidingWindowTicks, cacheEntry.AbsoluteCapTicks);
            _store.TryUpdate(key, newEntry, cacheEntry); // CAS — safe to lose race
        }
    }

    value = cacheEntry.Value;
    return true;
}
LineWhat's happening
TryGetValueSingle dict lookup — no lock, ConcurrentDictionary segment-level read.
DeadlineTicks ≤ nowExpired entries are NOT removed here. They linger until the sweep timer fires. TryGet just declares them dead.
remaining ≤ window/3Lazy-refresh threshold. Only the last third of a sliding window triggers a deadline extension. Prevents every hot-path read from doing a CAS write.
AbsoluteCapTicks > 0Sliding TTL is always clamped to the original absolute deadline. When SlidingTtl is not set, AbsoluteCapTicks is the same as DeadlineTicks — no confusion.
TryUpdate (CAS)Compare-and-swap on the struct. If another thread refreshed first, this silently fails — correct, because the deadline is already extended.

5 Gotchas read before touching TTL math

⚠ Sliding refresh is lazy, not eager
Deadline extension only triggers when remaining ≤ SlidingWindowTicks / 3. A key with a 30 s sliding window accessed 1 s after Set will not refresh — it refreshes only in the final 10 s. Don't expect "touch = full reset".
⚠ Sweep timer fires immediately at construction
new Timer(..., TimeSpan.Zero, sweepInterval) — the first sweep runs on construction, before any entries exist. Harmless, but surprising in tests if you're watching the sweep count. Tests disable this by passing sweepInterval: TimeSpan.FromHours(1) and calling SweepExpiredEntries() manually.
⚠ Count includes stale (not-yet-swept) entries
Count is _store.Count — it counts all entries including expired ones that haven't been swept yet. After expiry but before sweep, Count is inflated. Use it for capacity estimates, not exact live-entry counts.
⚠ TTL uses Stopwatch ticks, not DateTime ticks
Stopwatch.Frequency ticks ≠ TimeSpan.Ticks (10M/s). The conversion: (long)Math.Ceiling(ttl.TotalSeconds * Stopwatch.Frequency). Never mix the two. This also means TTL is monotonic and unaffected by clock adjustments.
⚠ AbsoluteCapTicks == 0 means "no separate absolute cap"
When only AbsoluteTtl is set (no SlidingTtl), AbsoluteCapTicks is set but SlidingWindowTicks is 0 — the sliding refresh branch is never entered. When both are set, AbsoluteCapTicks acts as the hard ceiling. The check AbsoluteCapTicks > 0 in TryGet guards this.
⚠ Double-Dispose in Runner.cs
Runner.cs calls cache.Dispose() both after Task.WhenAll and in finally. TtlCache.Dispose doesn't guard against double-dispose — the second call on an already-disposed Timer throws. Known issue; fix by adding an _disposed flag or using using.
⚠ Sweep latch prevents re-entrancy, not concurrency with Set/TryGet
_sweepRunning only blocks a second sweep from overlapping itself (timer firing while previous sweep is still running). Set/TryGet run concurrently with sweep at all times — that's fine because ConcurrentDictionary.TryRemove is safe, but be aware the sweep can delete an entry a TryGet is mid-read.
